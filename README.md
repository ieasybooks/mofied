# Mofied · مفيد

The standalone web, iOS and Android clients for **mofied.com**. Open directly into a finite session of curated media and reminders, with no account or home screen.

All three clients use the deployed Faqieh session API by default: `https://faqieh.com/api/v1/mofied/session?locale=ar`. Rails supplies the ordered plan and R2 serves the media. Development fixtures are an explicit opt-in; API failures never fall back to them.

## Development

Install [mise](https://mise.jdx.dev), then from this checkout:

```sh
mise install
mise exec -- bun install --frozen-lockfile
mise exec -- bun run dev
```

Open `http://localhost:5173` for the live API. Vite proxies the session request locally so production CORS does not need to allow localhost. Explicit development scenarios:

- `/?fixture=normal`: real media → Quran reminder → real media → ending.
- `/?fixture=long-title`: long title and speaker portrait.
- `/?fixture=missing-portrait`: name without a portrait.
- `/?fixture=unavailable`: failed stream replaced by a supplied spare.

The sample 10-minute budget and 20-second reminder are fixture values, not product-wide limits. Every page load/refresh and native app launch requests a fresh session; leaving and returning to the native app continues the same one. Progress is never saved to the device. Fixtures remain development-only.

The web build is configured for Cloudflare Workers Static Assets at `mofied.com`. ## Native development

```sh
mise exec -- bun run dev:mobile
# Explicit mock mode for deterministic local QA:
EXPO_PUBLIC_FIXTURE=normal mise exec -- bun run dev:mobile
```

Build an installed development app with Android Studio/SDK or Xcode available:

```sh
mise exec -- bun run --cwd apps/mobile android
# macOS / Xcode:
mise exec -- bun run --cwd apps/mobile ios
```

Native projects are generated by Expo and ignored by Git. Android needs `ANDROID_HOME` pointing to your SDK; use Java 21 from mise. iOS compilation requires a Mac. For a connected Android device, Metro can be reached using `adb reverse tcp:8081 tcp:8081`.

Development builds can show Metro's bundle-download banner at launch. Check the actual startup presentation in a standalone Release build: `bun run --cwd apps/mobile android --variant release` or `bun run --cwd apps/mobile ios --configuration Release`. These embed the JavaScript bundle and do not need Metro. Rebuild native projects after changing the `expo-splash-screen` configuration; exports and hot reload cannot update the OS launch screen. The dark native mark stays visible through font setup, then the matching circular loader covers session loading. The web product renders the same loading artwork before JavaScript starts.

Use a **development build**, not Expo Go, to test interruptions. A small, version-pinned `expo-video` patch exposes platform interruption events; Expo autolinking is configured to build that package from source. See [playback integration](docs/native-playback.md).

`bun run --cwd apps/mobile web` is a convenient browser preview of the React Native layout. It uses a web playback adapter and does not verify native lifecycle behavior. The actual web product is `apps/web`.

### Share links and deep links

Share links are `https://mofied.com/?start=<mediaId>`. The apps claim `https://mofied.com/` through `apple-app-site-association` and `assetlinks.json` in `apps/web/public/.well-known/`, which only work once deployed and fetched by Apple and Google. To exercise the in-app handling before that:

```sh
# iOS simulator: the app's own scheme reaches the same link handler.
xcrun simctl openurl booted "mofied://?start=<mediaId>"
# Android: an explicit VIEW intent, as a tapped mofied.com link sends.
adb shell am start -a android.intent.action.VIEW -c android.intent.category.BROWSABLE -d "https://mofied.com/?start=<mediaId>" com.mofied.app
```

The `com.mofied.app` App ID has the Associated Domains capability that store builds need.

### Releasing

Commit titles follow [Conventional Commits](https://www.conventionalcommits.org/), from which release-please keeps a release pull request with the next versions: the web and the apps are versioned separately. Merging it deploys mofied.com and submits the apps to the App Store, Google Play and AppGallery, which publish each version once approved. Store listings, release notes and screenshots live in [`apps/mobile/store/`](apps/mobile/store/README.md). See [releasing](docs/releasing.md).

## Repository layout

| Path                 | Responsibility                                                      |
| -------------------- | ------------------------------------------------------------------- |
| `apps/web`           | React, Vite, Tailwind; native HLS where available, otherwise hls.js |
| `apps/mobile`        | Expo, React Native, expo-video; iOS and Android                     |
| `apps/mobile/store`  | Store listings, release notes, reviewer notes and screenshots       |
| `packages/contracts` | Versioned Zod wire contract and HTTP provider                       |
| `packages/session`   | Shared session controller, time accounting and navigation           |
| `packages/design`    | Approved mark, fonts, colors and UI copy                            |
| `packages/fixtures`  | Development-only session plans with public media URLs               |
| `docs/design`        | Approved screen references and decisions                            |

The workspace follows the apps/packages organization discussed with the t3code reference. It does not copy t3code's desktop agent architecture or add a JavaScript backend. Keep this checkout beside the private Faqieh Rails checkout; neither repository is nested in the other.

## API configuration

No environment file is needed for production. To test another HTTPS endpoint, copy the relevant `.env.example` to `.env.local` in `apps/web` or `.env` in `apps/mobile` and set `VITE_SESSION_API_URL` / `EXPO_PUBLIC_SESSION_API_URL`. These are public configuration values, never secrets. An explicit endpoint takes precedence over mock selection. UI-language changes preserve the current server plan; an English plan can be requested with a `?locale=en` endpoint override.

[Contract documentation](docs/session-contract.md), [JSON Schema](docs/session.schema.json) and [example response](docs/session.example.json) describe the integration. Rails keeps publishing, curation and session planning; R2 serves the media directly.

## Verification

```sh
mise exec -- bun run check
mise exec -- bun run mobile:export
mise exec -- bunx playwright install chromium
mise exec -- bun run test:e2e
```

For real headed tab lifecycle testing on Linux:

```sh
HEADED=1 xvfb-run -a mise exec -- bun run test:e2e
```

Set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` if using an existing Chrome binary. Tests use a generated local MP4, not private media. [Verification notes](docs/verification.md) distinguish automated tests, build checks and device checks.

The optional live integration check serves the production bundle under the deployed origin and verifies real API CORS, decoded HLS and a fresh session after refresh (two public session requests):

```sh
mise exec -- bun run build
LIVE_API=1 HEADED=1 mise exec -- bunx playwright test tests/live-api.spec.ts
```
